# المستشار الأكاديمي الذكي - Smart Academic Advisor
> **AI-Based Credit-Hour Academic Guidance & Advising System**  
> Built for Computer Science Credit-Hour University Programs (Ibn Al-Haitham Compatible).

---

## 🏛️ نظرة عامة على النظام (Overview)

**المستشار الأكاديمي الذكي** هو نظام متكامل للإرشاد والتوجيه الأكاديمي يعمل فوق أنظمة شؤون الطلاب (مثل نظام ابن الهيثم). لا يستبدل النظام القائم، بل يوفر طبقة ذكية لإدارة الخطط الدراسية، والتنبؤ بمخاطر التعثر الأكاديمي، وخطة إنقاذ المعدل التراكمي (GPA Recovery)، وتقديم التوصيات الذكية المشروحة، وفق لائحة الساعات المعتمدة الرسمية.

### ⚖️ المبدأ المعماري الحاكم (Core Architectural Principle)
```
الذكاء الاصطناعي يقترح  ──►  محرك اللائحة يتحقق  ──►  المرشد الأكاديمي يعتمد  ──►  الطالب يستلم الخطة
(AI Recommends)          (Rules Engine Validates)    (Advisor Approves)            (Student Enrolls)
```
* **محرك اللائحة الأكاديمية (Rules Engine)** هو المرجع الحاسم الذي لا يمكن تجاوزه بأي اقتراح ذكاء اصطناعي.
* **كل توصية مقرونة بتفسير واضح (Explainable Recommendations)** يبين سبب التوصية، وسلاسل فتح المقررات المستقبلية، وتفادي بؤر التعطيل (Bottlenecks).

## 📐 قواعد اللائحة الأكاديمية المطبقة (Academic Bylaws)

1. **العبء الفصلي الأقصى حسب المعدل التراكمي (GPA-Based Credit Limits):**
   * معدل $\ge 3.00$: حتى **21 ساعة معتمدة**.
   * معدل $2.00 \le \text{GPA} < 3.00$: **18 ساعة معتمدة**.
   * معدل $1.00 \le \text{GPA} < 2.00$ (تحت الإنذار): **15 ساعة معتمدة**.
   * معدل $< 1.00$: **12 ساعة معتمدة كحد أقصى**.
   * الفصل الصيفي: معدل $\ge 3.00$ يسمح بـ **9 ساعات**، وغير ذلك **6 ساعات**.
   * الطالب المستجد بالفصل الأول: حتى **21 ساعة**.
2. **سقف تقدير إعادة المقررات بعد الرسوب (Retake Grade Caps):**
   * الإعادة الأولى: سقف التقدير **B+ (3.2 نقطة)**.
   * الإعادة الثانية: سقف التقدير **C+ (2.6 نقطة)**.
   * الإعادات اللاحقة: سقف التقدير **D+ (2.0 نقطة)**.
3. **الإنذارات الأكاديمية والفصل (Academic Warnings & Dismissal):**
   * معدل تراكمي أقل من 2.00 يولد إنذاراً أكاديمياً.
   * 4 إنذارات متتالية أو 6 إجمالية تعرض الطالب للفصل، مع تطبيق بند فرصة التخرج الاستثنائية لمن أنجز $\ge 80\%$ من الساعات.
4. **أهلية مشروع التخرج (CS 498 / CS 499):**
   * يشترط إنجاز $70\%$ على الأقل من ساعات البرنامج ($134 \times 0.70 \approx 94$ ساعة).
5. **أهلية التدريب الميداني الصيفي:**
   * يشترط إنجاز $30$ ساعة معتمدة قبل التسجيل.
6. **الحد الأقصى للغياب (الحرمان من الامتحان النهائي):**
   * يُسمح لكل طالب بغياب نسبة `MAX_ABSENCE_PERCENT` (افتراضياً **25%**) من محاضرات وسكاشن الفصل (`TEACHING_WEEKS` أسبوعاً، افتراضياً **14**).
   * القيمتان قابلتان للتعديل من صفحة «اللائحة» في حساب مدير النظام، وكل الحسابات والتنبيهات تتبعهما فوراً.
   * يصل الطالب تنبيه عند استهلاك نصف المسموح، ثم «آخر فرصة» عند استهلاكه كله، ثم «تجاوز الحد» مع إبلاغ أستاذ المادة والمعيد والمرشد.
7. **إعادة المقرر لتحسين المعدل:** يجوز إعادة مقرر نجح فيه الطالب بتقدير D+ أو D أو D-، ولا يُسجَّل مقرر يدرسه الطالب بالفعل في الفصل نفسه.

## 🛠️ التقنيات المستخدمة (Tech Stack)

* **الواجهة الأمامية (Frontend):**
  * React 19 + TypeScript + Vite
  * Tailwind CSS v4 + Motion
  * Lucide Icons
  * دعم كامل للغتين: العربية الافتراضية (RTL) والإنجليزية (LTR) مع مراعاة كاملة للاتجاهات.
* **الواجهة الخلفية والمحركات (Backend & Engines):**
  * Node.js + Express + TypeScript
  * محرك اللائحة الأكاديمية الصارم (`AcademicRulesEngine`)
  * محرك حساب المعدل وسقف الإعادة (`GpaEngine`)
  * محرك التوصيات الذكية المشروحة (`RecommendationEngine`)
  * مولد خطة التخرج التلقائي (`StudyPlanner`)
  * مخطط إنقاذ المعدل التراكمي الاستراتيجي (`GpaImprovementPlanner`)
  * محرك تقييم المخاطر الأكاديمية (`AcademicRiskEngine`)
  * سجل العمليات الأكاديمية وتتبع التدقيق (`AuditLog`)

## 🎨 الواجهة ونظام التصميم (UI & Design System)

الواجهة مبنية على فكرة **«الإرشاد كخريطة طريق»**: القائمة الرئيسية خط مترو كل صفحة فيه محطة، ولوحة الطالب تعرض مساره من البداية حتى التخرج بعلامة «أنت هنا».
- ألوان لافتات الطرق (أخضر + أصفر المسار) وخط Alexandria المضمَّن (يعمل بدون إنترنت).
- بحث سريع وتنقل من لوحة المفاتيح: `Ctrl + K`.
- التفاصيل الكاملة للألوان والمكوّنات والقواعد: [`docs/DESIGN_SYSTEM.md`](docs/DESIGN_SYSTEM.md).
- اسم الجامعة/الكلية في المستندات المطبوعة يُعدَّل من ملف واحد: `src/config/institution.ts`.

## 🚀 التشغيل المحلي (Quick Start)

### 1. تثبيت الاعتماديات والتشغيل
```bash
# تثبيت الاعتماديات
npm install

# تشغيل الخادم والواجهة (Full-Stack dev server on Port 3000)
npm run dev
```

### 2. تشغيل الاختبارات الآلية للوائح
```bash
npm run test
```

سيعمل التطبيق مباشرة على: `http://localhost:3000`

### 3. رمز QR في السجل الأكاديمي الموثق
الرمز يحمل رابطاً قصيراً موقّعاً يفتح صفحة تحقق عامة (`/verify/<رمز التحقق>`) تعرض بيانات الطالب ومعدله ومقرراته، ولا يمكن تزويره، ويظل صالحاً بعد إعادة تشغيل السيرفر.
- **محلياً (`npm run dev`)**: يضع النظام عنوان الجهاز على الشبكة تلقائياً، فامسح الرمز بموبايل متصل بنفس شبكة الواي فاي. لو سألك Windows عن جدار الحماية لـ Node.js اختر السماح على الشبكات الخاصة.
- **بعد النشر**: يُستخدم الرابط العام تلقائياً على Render، أو اضبط `PUBLIC_APP_URL` على العنوان الذي تريد أن يفتحه الموبايل (مطلوب مع Docker).

### 4. تسجيل الحضور برمز QR
- أستاذ المادة (أو المعيد للسكشن) يبدأ المحاضرة من صفحة «الحضور»، فيظهر رمز QR وكود من 6 أرقام يتجددان كل 30 ثانية (يمكن عرضهما بملء الشاشة على البروجكتور).
- الطالب يمسح الرمز بكاميرا الهاتف مباشرة (يفتح رابطاً يسجل حضوره بعد تسجيل الدخول)، أو من صفحة «الحضور» داخل النظام، أو يكتب الكود. الحضور بعد 15 دقيقة يُسجَّل «متأخر».
- الماسح داخل المتصفح يحتاج اتصالاً آمناً **https** (متوفر على Render). على `http` محلياً يمكن تصوير الرمز من زر «صوّر الرمز» أو كتابة الكود.
- عند إنهاء المحاضرة يُسجَّل الباقون غائبين، وتصل تنبيهات الغياب، ويصل للدكتور والمعيد ملخص بعدد الحاضرين مع كشف **Excel** للمحاضرة، وكشف آخر للفصل كله من «تقرير الغياب».
