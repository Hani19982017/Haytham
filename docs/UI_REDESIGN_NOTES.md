# ملاحظات إعادة تصميم الواجهة

## ما الذي تغيّر

- **هوية بصرية جديدة بالكامل** لكل الصفحات والنوافذ (التفاصيل في [`DESIGN_SYSTEM.md`](DESIGN_SYSTEM.md)).
- **التنقل**: القائمة الجانبية حُذفت؛ القائمة الآن «خط مترو» أعلى الصفحة لكل دور، مع بحث سريع `Ctrl + K`.
- **صفحة الدخول**: خريطة مسار الدرجة العلمية (المستويات ← المسارات الثلاثة ← مشروع التخرج ← التخرج) وكل حسابات التجربة السبعة.
- **لوحة الطالب**: مسار من البداية حتى 134 ساعة بمحطات اللائحة وعلامة «أنت هنا»، ومقياس المعدل يوضح حد الساعات المسموح لكل نطاق، و«خطوتك التالية» حسب وضع الطالب.
- **التسجيل الفصلي**: مراحل واضحة (المقترح ← فحص اللائحة ← المسودة ← الأسبوع ← الإرسال)، وجدول أسبوعي ملوّن يظهر التعارض بالأحمر.
- **المرشد**: قائمة فرز حسب الخطر بفلاتر قابلة للضغط، وبطاقات قرار للخطط، وسجل الطلاب مع السجل الموثق.
- **الأدمن**: لوحة حالة الخدمات، المقررات، الشعب، اللائحة، الاستيراد، وسجل العمليات كخط زمني.
- **رئيس القسم**: توزيع الخطر، بؤر الرسوب، وضغط المقاعد كأشرطة واضحة.
- كل النوافذ المنبثقة موحّدة: تُغلق بـ Esc، وعند الطباعة تُطبع النافذة وحدها (السجل الموثق، الاستمارة).
- الخط مضمَّن في المشروع (يعمل بدون إنترنت)، والواجهة كاملة بالعربية والإنجليزية وعلى الموبايل.

## أخطاء كانت موجودة واتصلحت

**التسجيل والجدول**
- كشف تعارض المواعيد لم يكن يعمل مع قاعدة البيانات: السيرفر كان يفقد أيام ومواعيد الشعب عند قراءتها (`server/repositories/offeringRepository.ts`)، فكان الجدول المقترح قد يحتوي تعارضاً لا يظهر. أصبحت المواعيد تُستخرج من نص الموعد المحفوظ.
- رسالة الإنذار كانت ثابتة («إنذار رقم 2»، «15 ساعة») وأصبحت من بيانات الطالب الفعلية.
- خطأ في أولوية الشروط (`&&` / `||`) كان يضع مقررات في فترات خاطئة بالجدول الأسبوعي.
- البحث في نافذة «إضافة مقرر» كان غير متصل؛ أصبح يعمل بالكود أو الاسم.
- رسائل اللائحة (شعبة ممتلئة، مقرر مجتاز، سقف الإعادة، الحد الأدنى للعبء) كانت لا تظهر.

**الأستاذ**
- حفظ الدرجات كان يحفظ في السيرفر ثم يتعطل في الواجهة (اسم حقل خاطئ في الاستجابة) فلا يظهر تأكيد ولا يتحدث الجدول.
- تغيير المقرر كان يُبقي درجات المقرر السابق في الحقول.
- الحضور كان يُحفظ عند كل خروج من الحقل حتى بدون تغيير، فيرسل إنذار غياب مكرر للطالب.

**المرشد والأدمن ورئيس القسم**
- بطاقة «تحت معدل 2.00» عند المرشد لم تكن تفعل شيئاً؛ أصبحت فلتر.
- حقل المتطلبات السابقة في نموذج المقرر لم يكن يقبل الفاصلة، فلا يمكن إضافة أكثر من متطلب.
- أخطاء استيراد CSV لم تكن تظهر.
- حقول السعة وقواعد اللائحة كانت تُحفظ عند كل خروج من الحقل فتملأ سجل العمليات بتعديلات وهمية.
- بطاقة «طلاب في خطر» كانت تفتح سجل العمليات.
- صفحة رئيس القسم كانت تبقى في التحميل للأبد عند فشل الطلب، وقد تعرض `NaN%`.

**الطالب**
- محاكي «ماذا لو» كان يعرض «+» حتى لو المعدل نزل.
- خطة التخرج كانت تعرض أرقاماً ثابتة غير حقيقية (معدل «2.45+»، «2.30»، «56 ساعة») واسم مرشد ثابت.
- زر «السجل الموثق» في الشريط العلوي كان يعرض سجل طالب آخر (عمر) لأي مستخدم غير طالب؛ أصبح للطالب فقط، والمرشد وشؤون الطلاب يفتحون سجل كل طالب من القائمة.

**عام**
- أي رابط غير معروف كان يحوّل كل الأدوار إلى لوحة الطالب؛ أصبح يحوّل كل دور لصفحته.
- لوحات الأدمن والمرشد كانت تعيد تحميل كل البيانات عند كل تنقل بين التبويبات.
- `npm run dev` على Windows لم يكن يُنشئ جداول قاعدة البيانات (صيغة متغير البيئة كانت خاصة بـ bash).

## الاختبار الذي تم

- تشغيل المشروع كاملاً (الواجهة + الـ API + PostgreSQL تجريبية بالبيانات الأصلية).
- اختبار آلي (Playwright) دخل بكل حسابات التجربة السبعة، وفتح كل صفحة، وضغط كل زر وتبويب وفلتر وقائمة، وتأكد أن لكل ضغطة أثراً (انتقال، نافذة، طلب للسيرفر، أو تغيير في الصفحة) بدون أخطاء.
- سيناريوهات كاملة على الـ API: إرسال الجدول، اعتماد/رفض الخطط، رصد الدرجات والحضور، إضافة وتعديل وحذف المستخدمين وإعادة كلمة المرور وإسناد الطلاب، إضافة مقرر، تعديل السعة واللائحة، استيراد CSV، التدريب الصيفي، طباعة السجل الموثق، تغيير اللغة، البحث السريع.
- فحص العرض على شاشة الموبايل (390px) بالعربية والإنجليزية.
